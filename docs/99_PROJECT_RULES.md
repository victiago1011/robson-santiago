# Regras Rápidas do Projeto

## Obrigatório

- Ler `/docs/00_START_HERE.md` antes de trabalhar no projeto.
- Respeitar `01_AI_CONSTITUTION.md`.
- Analisar antes de implementar.
- Propor o menor plano suficiente.
- Informar arquivos afetados.
- Aguardar a resposta exata `APROVADO` antes de modificar o projeto.
- Validar o projeto após alterações aprovadas.
- Relatar exatamente o que mudou.

## Nunca fazer sem aprovação

- instalar dependências;
- trocar stack;
- adicionar banco de dados;
- adicionar autenticação;
- adicionar CMS;
- adicionar pagamento;
- adicionar newsletter;
- alterar identidade visual aprovada;
- criar novas funcionalidades;
- refatorar áreas fora do escopo;
- remover funcionalidades existentes;
- fazer commit ou push.

## Conteúdo

Nunca inventar dados sobre Robson Santiago, livros, podcast, projetos, avaliações, biografia, redes sociais ou resultados.

## Design

- Robson Santiago é a marca central.
- Linguagem editorial, elegante e minimalista.
- Google Stitch é referência visual, não autoridade sobre arquitetura/código.
- Responsividade deve ser real e implementada desde o início de cada seção.
- Validar como referência aproximadamente 390px (mobile), 768px (tablet) e 1440px (desktop).
- Uma seção visual não está concluída se funcionar apenas em desktop.
- Mobile pode reorganizar layout, ordem, tamanhos e espaçamentos; não deve ser apenas o desktop comprimido.
- Não transformar o site em aparência de startup, dashboard ou template genérico.

## Engenharia

- Código simples e legível.
- TypeScript.
- Tailwind existente.
- Sem dependências desnecessárias.
- Componentes apenas quando agregarem organização/reutilização.
- Preservar acessibilidade e semântica.

## Git

O usuário controla commits e pushes. Não executar automaticamente.

## Regra de ouro

**Não aproveitar uma solicitação pequena para fazer mudanças grandes.**

Se algo adicional parecer útil, sugerir separadamente e aguardar aprovação.
